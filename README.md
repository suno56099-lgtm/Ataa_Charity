# منظومة جمعية عطاء الخيرية (Ataa Association)
### منصة رقمية سحابية ذكية لإدارة المستفيدين ونقاط السلع التموينية والأكواد الشهرية والتسليم الميداني

---

## 🌟 نظرة عامة على النظام

منظومة **جمعية عطاء** هي حل برمجي متكامل ومصمم خصيصاً للمؤسسات والجمعيات الخيرية لإدارة دورة الدعم الغذائي والسلعي بكفاءة وشفافية مطلقة. تتيح المنظومة:
1. **إدارة المستفيدين**: تسجيل بيانات الأسر، التحقق الآلي من الرقم القومي المصري (14 رقماً)، حجب الأرقام القومية بحماية أمنية وتوثيق كل عملية كشف في سجل التدقيق (Audit Log).
2. **إدارة المنتجات ونقاط السلع**: تعريف السلع الغذائية (زيت، أرز، سكر، لحوم، إلخ) وتحديد تكلفتها بنقاط العطاء.
3. **الأكواد الشهرية الذكية (One-Time Codes)**: توليد كود شهري فريد عشوائي مكون من 6 أرقام لكل مستفيد نشط شهرياً مع منع التكرار، ودعم إرسال الرسائل النصية القصيرة (SMS) عبر الهاتف المحمول أو بوابة الإرسال الجماعي.
4. **التسليم والصرف الميداني الذري (Atomic RPC)**: تنفيذ الصرف عبر معاملة قاعدة بيانات ذرية واحدة تضمن التحقق من الكود والشهر، خصم النقاط، تسجيل الأصناف وتفاصيل التسليم، وتغيير حالة الكود إلى "تم الصرف" بدون أي احتمالية للصرف المزدوج.
5. **سجل العمليات والتدقيق الأمني**: مراقبة حية لجميع عمليات الصرف، وكشف الأرقام القومية، وتوليد الأكواد مع إمكانية التصدير بصيغة CSV المتوافقة مع اللغة العربية.
6. **إدارة فريق العمل والأدوار (RBAC)**: حسابات المدراء (Admin) وموظفي الصرف (Staff)، مع تأمين تام عبر سياسات الأمان على مستوى الصف (RLS).
7. **تطبيق ويب تقدمي (PWA)**: قابل للتثبيت على الهواتف والأجهزة اللوحية والعمل دون اتصال بالإنترنت.

## 🚀 ربط المنظومة بقاعدة بيانات Supabase حقيقية

تم تصميم طبقة الوصول للبيانات (`src/services/dataService.ts`) لتكون متوافقة بنسبة 100% مع Supabase:

1. أنشئ مشروعاً جديداً على [Supabase](https://supabase.com).
2. افتح **SQL Editor** في لوحة تحكم Supabase.
3. انسخ محتوى الملف `supabase/schema.sql` والصقه ونفذه لإنشاء الجداول وسياسات الأمان (RLS).
4. انسخ محتوى الملف `supabase/rpc_deliver.sql` ونفذه لإنشاء دالة الصرف الذري `process_charity_delivery`.
5. انسخ محتوى الملف `supabase/seed.sql` ونفذه لتعبئة البيانات التجريبية الأولية.
6. في إعدادات التطبيق أو ملف البيئة المحلي، قم بتعيين المتغيرين:
   ```env
   VITE_SUPABASE_URL="https://your-project.supabase.co"
   VITE_SUPABASE_ANON_KEY="your-anon-key"
   ```
7. عند عدم توفر هذه المتغيرات، تعمل المنظومة تلقائياً بمحرك محلي متطور (LocalStorage Data Provider) يحاكي تماماً دالة المعاملة الذرية وجميع القيود لتمكين التقييم والتجربة الميدانية السريعة.

## 🛡️ نموذج الأمان وموثوقية المعاملات (Atomic Integrity)

- **حجب الرقم القومي**: يتم إخفاء 4 أرقام وسطية من الرقم القومي افتراضياً في جميع الجداول، ولا يتم إظهار الرقم الكامل إلا بطلب صريح مع تسجيل هوية الموظف وتاريخ العملية في جدول `audit_logs`.
- **منع الصرف المزدوج**: دالة `process_charity_delivery` تستخدم قفل السطر `FOR UPDATE` في PostgreSQL، وتتحقق من مطابقة الشهر وحالة الكود ورصيد النقاط، وتجري عملية الخصم والتسجيل داخل كتلة ذرية لا تقبل التجزئة.

## 🐙 النشر والتشغيل على GitHub و GitHub Pages

المشروع مُهيأ ومجهز بالكامل للعمل المباشر مع **GitHub**:

### 1. رفع المشروع إلى مستودع GitHub الخاص بك:
```bash
# إنشاء مستودع جديد على GitHub ثم تنفيذ الأوامر التالية:
git add .
git commit -m "Initial commit: منصة جمعية عطاء الخيرية"
git remote add origin https://github.com/<YOUR_USERNAME>/<YOUR_REPO_NAME>.git
git branch -M main
git push -u origin main
```

### 2. التفعيل التلقائي للنشر على GitHub Pages:
يحتوي المشروع على ملف سير عمل مؤتمت بالكامل (`.github/workflows/deploy.yml`):
1. افتح صفحة المستودع على **GitHub**.
2. انتقل إلى **Settings** > **Pages**.
3. تحت قسم **Build and deployment**، اختر **Source: GitHub Actions**.
4. بمجرد قيامك بأي `git push` لفرع `main`، سيقوم GitHub ببناء الموقع ونشره تلقائياً على الرابط:
   `https://<YOUR_USERNAME>.github.io/<YOUR_REPO_NAME>/`
